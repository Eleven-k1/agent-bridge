# 固定本地 OpenAI 兼容中转连接设计

**日期：** 2026-09-26  
**状态：** 待用户评审  
**目标：** 在现有 Fake Provider 闭环之上，增加一个连接固定本地中转服务的真实 Provider。

## 1. 范围

第一阶段只支持一个固定地址：

```text
http://127.0.0.1:8080
```

不实现多连接配置、远程地址配置、HTTPS 配置、API Key、Windows 凭据管理器或其他 Provider 协议。

真实模型请求仍然沿用现有 M2 ModelGateway、M5 SQLite 事件持久化、M6 本地鉴权/转发和 M7 Electron 界面链路。Provider 只负责 HTTP 请求、响应解析和 Provider 错误归类，不直接写数据库、不访问项目文件、不执行工具。

## 2. 模型发现与选择

应用提供“刷新模型”操作，向固定地址请求：

```text
GET http://127.0.0.1:8080/v1/models
```

成功且响应符合 OpenAI 兼容格式时，读取 `data[].id` 作为可选模型列表。模型列表不可用、路径不存在或响应格式不兼容时，不阻断真实请求；界面显示脱敏后的失败类别，并允许用户手动填写模型名。

模型请求必须明确使用一个模型名。没有自动发现结果时，手动输入的模型名作为请求参数传给中转服务。

## 3. 模型请求

请求地址固定为：

```text
POST http://127.0.0.1:8080/v1/chat/completions
```

请求使用 OpenAI 兼容 JSON 格式，映射现有 `ModelRequest` 的系统提示、消息、模型和超时策略。

支持两种响应：

- 流式：发送 `stream: true`，解析 SSE `data:` 行、增量文本、完成原因和可选 usage。
- 非流式：发送 `stream: false`，读取 `choices[0].message.content`，转换成统一的 `DELTA` 后再产生 `COMPLETED`。

Provider 输出必须转换成现有 `ProviderEvent`，上层不感知 HTTP 或 SSE 细节。

## 4. 错误、取消与重试

错误统一归类为现有 Provider 错误类别：

- `401/403`：认证或权限错误（即使当前不发送认证头，也保留分类）
- `429`：限流
- 网络连接、DNS、断开：网络错误
- 连接、首字节、流式空闲超时：超时
- `4xx` 请求错误或响应格式错误：协议错误
- `5xx`：服务端错误
- 用户主动停止：取消

只在尚未收到有效内容前，对可重试的网络、超时、限流和服务端错误执行有限重试。收到内容后失败不自动重发完整请求。取消后丢弃后续增量。

错误进入界面、事件和日志前必须脱敏，不保存响应正文、请求头或任何未来可能出现的凭据字段。

## 5. 桌面端交互

桌面端增加最小的真实连接控制：

- 显示固定中转地址和当前连接状态。
- 提供刷新模型按钮。
- 展示自动发现的模型列表。
- 提供手动模型名输入作为回退。
- 提供连接测试/真实请求入口。
- 显示流式文本、正式事件、完成状态和脱敏错误。

不增加 Provider 管理页、API Key 输入框或凭据存储逻辑。

## 6. 测试与验收

后端单元测试覆盖：

- `/v1/models` 成功、404、异常 JSON 和空列表。
- SSE 增量、`[DONE]`、usage、完成原因和空增量。
- 非流式响应转换。
- 401、429、4xx、5xx、网络失败、超时、取消和重试边界。
- API 请求不包含 Authorization 头。
- 现有 Fake Provider、Fake Tool、SQLite、断线恢复和协议测试继续通过。

桌面端测试覆盖模型发现成功/失败回退、手动模型名提交和错误展示。完成前同步更新 `README.md`、`docs/current-status.md` 和 Provider 模块文档，并清理测试数据库、缓存和一次性验证文件。

## 7. 明确不在范围内

- Anthropic Messages、Z.AI 或其他协议。
- 多 Provider、多地址、多用户或远程服务。
- API Key、OAuth 或其他认证配置。
- 真实文件写入、Shell、Git、下载和安装依赖。
- 自动多智能体编排和完整产品化任务工作流。
