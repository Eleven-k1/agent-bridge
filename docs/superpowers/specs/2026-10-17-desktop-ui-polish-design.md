# 桌面端工作台视觉升级设计

## 目标

把当前默认浏览器样式的 Electron 工作台升级为深色专业控制台。用户打开界面后，应能快速识别连接状态、真实任务入口、模型选择、当前命令状态，以及临时流帧和正式事件的区别。

## 范围

- 只修改 `desktop/src/renderer/App.tsx` 的展示结构和样式，并按需要新增 renderer 样式文件。
- 保留现有 React 状态、桥接 API、命令处理、事件投影和所有 `data-testid`、ARIA label。
- 不改变后端协议、IPC 参数、任务状态机或 Relay 行为。
- 不引入 UI 框架或新的运行时依赖。

## 视觉方案

采用深色专业工作台：

- 页面背景使用深海蓝灰色，主面板使用稍亮的蓝灰色，辅以细边框和轻微阴影建立层级。
- 顶部使用产品标识、简短副标题和连接状态徽标；连接状态使用绿色、琥珀色、红色区分已连接、连接中和失败。
- 真实任务作为首要操作卡片，包含任务标题、说明、较大的多行输入框、模型选择区和高对比主按钮。
- Fake 任务与 Fake 工具放入“开发演示”次级操作组，视觉权重低于真实任务。
- 流式层与正式事件层使用并列结果卡片；通过标签、计数徽标和空状态文案强调“临时显示”和“持久化事实”的区别。
- 统一按钮、输入框、下拉框的高度、圆角、焦点环、禁用状态和错误提示，保证键盘操作可见。

## 交互与可访问性

- 保持现有 `Task request`、`Manual model`、`Available models` 可通过 label 查询。
- 保留所有按钮可访问名称和现有测试选择器。
- 空白任务仍不可提交；模型未选择时真实任务按钮仍不可提交。
- 错误信息使用高对比颜色，并在布局中保持可读，不依赖颜色单独表达状态。

## 验收标准

- 现有桌面端 24 项测试继续通过。
- TypeScript 类型检查和 Electron 构建继续通过。
- 新增或调整渲染测试，确认任务输入、模型输入、真实任务按钮和连接状态仍可定位。
- `git diff --check` 无空白错误，临时构建/测试残留不进入提交。

## 不做事项

- 不增加主题切换、持久化用户偏好、动画库、图标库或复杂响应式布局。
- 不把真实请求认证、模型发现或错误分类扩大到本轮 UI 改造。
