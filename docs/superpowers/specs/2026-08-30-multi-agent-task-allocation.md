# 多智能体协作桥梁软件：多 AI 任务分配方案

**日期：** 2026-08-30  
**状态：** 已经用户确认，当前任务分配依据  
**关联方案：** [多智能体协作桥梁软件方案](./2026-08-30-multi-agent-bridge-design.md)  
**用途：** 将第一版软件开发工作拆分为可由不同 AI 独立承担、交叉审查和集中集成的工作包

## 1. 文档边界

本文件是已生效的任务分配方案和可复制任务卡。用户已授权开始编码；具体实施顺序、依赖和目录由实施计划明确。

- 不决定由 ChatGPT、Claude 或 Zcode 永久承担某个角色。
- 不决定具体库、版本、目录名称、数据库、通信框架、打包工具或内部算法。
- 不预估工期，不替用户决定人员、模型调用费用或依赖选择。
- 实施方对具体技术选择、目录和阶段计划负责，选择前按项目规范调研可复用的开源项目；只有涉及重大产品取舍时才需要用户决定。
- 本方案制定方在开发完成后依据主方案、任务卡和真实证据负责验收。

## 2. 总体分工原则

### 2.1 按稳定边界拆分

任务按协议、编排、模型、安全执行、项目恢复、存储、通信、界面和验收拆分，不按模型品牌拆分，也不把页面直接等同于业务模块。

### 2.2 一个模块只有一个写入负责人

同一阶段内，一个模块及其核心文件只能由一名 AI 写入。其他 AI 可以只读审查、提出问题或提供补丁建议，但不能同时覆盖实现。

### 2.3 一个集成负责人

只有集成负责人可以修改跨模块胶水、批准公共契约变更和执行正式合并。模块实现 AI 不得为了让自己的代码运行而私自改变其他模块。

### 2.4 实现与验收分离

实现某模块的 AI 不能独自宣布该模块通过。安全、恢复、审批、写入锁和真实端到端流程必须由非作者 AI 复核。

### 2.5 先协议、后并行；先模拟、后真实

公共契约和模拟依赖稳定前，不启动大规模并行开发。各模块先通过契约测试和模拟服务，再接入真实模型、真实文件、真实命令和真实 Windows 环境。

## 3. 建议角色

| 角色 | 核心职责 | 写入权限 | 不承担的职责 |
|---|---|---|---|
| 架构与集成 AI | 公共契约、编排主干、跨模块集成、决策记录、合并 | 公共协议、编排和集成区域 | 不代替用户决定产品取舍，不包揽所有外围功能 |
| 安全与项目后端 AI | 权限、审批、工具、Git、快照、恢复、进程管理 | 安全和项目执行区域 | 不修改 UI，不自行改变公共协议 |
| 模型与桌面 AI | 模型适配、本地通信、工作台和连接设置 | 适配器、通信和界面区域 | 不直接操作项目文件，不在前端实现安全规则 |
| 独立验收 AI | 黑盒测试、故障注入、安全审查、文档一致性 | 默认只读；测试区域可写 | 不直接修复被验收模块，不自行降低验收标准 |

这些是逻辑角色，不是对具体模型品牌的永久绑定。角色应根据同题基准测试、上下文稳定性、代码操作能力和审查质量动态分配。

## 5. 公共契约所有权

M0 公共契约已以项目根目录的 `M0-公共协议与数据契约-v0.5.1-最终版.txt` 生效，先于其他模块实现。它定义：

- `Task`：任务身份、项目、目标、当前阶段和最终状态。
- `Agent`：模型、角色、能力、主管或执行者状态。
- `Message`：发送者、接收者、类型、正文、引用、序号和可见性。
- `Command`：用户或系统提出的状态转换请求。
- `Event`：已经发生且不可更改的任务事实。
- `ModelRequest` 与 `ModelEvent`：统一模型请求、流式响应、取消和错误。
- `ToolRequest` 与 `ToolResult`：工具、参数、风险、审批、输出和文件变化。
- `ApprovalRequest` 与 `ApprovalDecision`：目标、原因、风险、范围、过期和决定。
- `WriteLease`：唯一写入者、目标任务、有效范围、获取、释放和失效规则。
- `Evidence`：测试、编译、命令、文件、外部来源和模型意见的引用。
- `Checkpoint`：任务恢复所需的稳定阶段和磁盘事实。
- `Error`：来源、类别、可重试性、用户影响和原始诊断引用。

所有命令和正式事件必须具有版本、作用域和幂等信息。`TASK` 作用域携带任务标识和运行标识，`WORKSPACE` 作用域携带工作区标识，`LOCAL_CONFIG` 作用域不强制要求任务或工作区标识。临时模型流式帧不是正式事件。字段名称和语义以 M0 最终版为准。

其他模块发现契约不够用时，只能提交接口变更单。未经 M0 负责人确认，不得直接改变公共字段或状态含义。

## 7. M0 任务卡：公共协议与数据契约

### 目标

建立所有模块共享的领域对象、命令、事件、状态转换、错误语义和契约测试，使 Python 内核、模型适配器、工具、存储、本地通信和 TypeScript 界面能够在不读取彼此内部实现的情况下协作。

### 明确不做

- 不接入真实模型。
- 不执行真实文件修改或命令。
- 不实现完整 UI。
- 不决定具体框架和数据库。
- 不编写业务功能之外的通用框架。

### 允许修改范围

- 公共契约、领域类型、Schema、示例事件和契约测试区域。
- 与契约直接相关的架构决策记录。

### 禁止修改范围

- 模型供应商实现。
- 安全工具实现。
- Git、快照和恢复实现。
- 桌面界面业务代码。

### 必须交付

- 版本化的任务、消息、模型、工具、审批、写入锁、证据、检查点和错误契约。
- 明确的任务状态转换表。
- Python 与 TypeScript 之间的一致性验证方式。
- Fake Provider、Fake Tool 和可重放事件样例。
- 契约兼容性测试和接口变更单模板。

### 验收重点

- 每个状态有明确进入条件、退出条件和非法转换。
- 暂停、取消、恢复、审批等待和异常状态不存在多种冲突解释。
- 工具成功不等于任务完成；模型意见不等于证据。
- 写入权限和审批不能只用 UI 状态或普通布尔值表达。

## 8. M1 任务卡：协作编排内核

### 目标

实现确定性的任务状态机和多智能体协作流程，支持主管动态组队、公开讨论、用户介入、方案审批、唯一执行者、验证、独立审查、返工和任务结束。

### 明确不做

- 不直接调用具体模型 SDK。
- 不直接访问 Electron 界面。
- 不直接操作文件、Git 或 PowerShell。
- 不自行保存 API Key。
- 不绕过 M3 的审批和 M4 的工具接口。

### 依赖

- M0 公共契约。
- M2 模型网关接口或 Fake Provider。
- M3 审批接口或 Fake Policy。
- M4 工具接口或 Fake Tool。
- M5 状态和事件存储接口。

### 必须交付

- 主管和参与者调度。
- 全量公开消息和 `@智能体` 路由。
- 用户插话、暂停、继续、停止、换主管、换执行者和重新分工。
- 方案审批等待和拒绝后的状态处理。
- 唯一执行者租约申请、释放和失效处理。
- 超时、有限重试、循环检测、熔断和技术硬上限。
- 主管失败时基于结构化状态切换备用主管。
- 不自动重放外部副作用的异常恢复流程。

### 必须测试

- 所有合法和非法状态转换。
- 暂停时不再启动新调用。
- 取消、超时和重复事件不会造成重复执行。
- 换主管或换执行者后不存在两个写入者。
- 三模型之一失败时的降级和交叉验证标记。
- 多轮无新证据时的熔断和用户接管。

## 9. M2 任务卡：模型网关与适配器

### 目标

把 ChatGPT 中转站、Claude 中转站和 Z.AI API 转换为统一模型接口，并隔离不同供应商、中转站和模型版本的协议差异。

### 明确不做

- 不决定任务应该由哪个模型执行。
- 不访问项目文件。
- 不执行工具。
- 不持有写入权限。
- 不把完整 API Key 写入日志、错误、缓存或项目数据。

### 允许修改范围

- 统一模型网关公共实现。
- 三类适配器各自独立区域。
- 模型协议测试、假服务器和响应夹具。

### 必须交付

- 连接诊断、模型名配置和可用性检查。
- 流式文本、结束、取消、超时和错误统一事件。
- 有限重试和可重试错误分类。
- 中转站非标准响应的隔离处理。
- 能力元数据和不支持能力的明确报告。
- 可使用假服务器重复验证的协议测试。

### 必须测试

- 正常流式响应。
- 流式响应中途断开。
- 无效凭据、限流、超时和服务端错误。
- 用户取消后停止继续产生有效业务事件。
- 不同错误格式映射到统一错误语义。
- 错误和诊断中不存在完整凭据。

## 10. M3 任务卡：安全、权限与审批

### 目标

建立程序强制执行的安全策略和审批票据，确保模型、UI 和其他模块不能绕过项目边界、敏感信息保护、危险操作审批和唯一写入者规则。

### 明确不做

- 不依靠提示词代替程序门禁。
- 不直接实现主管调度。
- 不直接决定产品取舍。
- 不把一次批准自动扩展到其他目标或后续任务。

### 必须交付

- 项目根目录和项目外访问策略。
- 敏感路径、密钥、证书、Token、大文件和二进制内容的识别与阻止接口。
- 危险文件操作、命令、下载、安装、外部执行和 Git 提交审批规则。
- 审批票据与具体目标、参数、风险和有效范围绑定。
- Windows 安全凭据抽象和统一脱敏接口。
- 唯一写入者租约的授权检查。
- 安全审计事件。

### 必须测试

- 路径逃逸、链接逃逸和项目外访问。
- 审批对象被修改后的失效。
- 拒绝、过期、撤销和应用重启后的审批失效。
- 假密钥和假私钥不会进入模型请求、日志和项目存储。
- UI 或模型直接请求高风险工具时仍被程序层拒绝。
- 同一时刻第二个执行者无法获得有效写权限。

## 11. M4 任务卡：受控工具、Git、快照与恢复

### 目标

提供所有真实项目副作用的唯一执行入口，覆盖文件操作、PowerShell/CMD、测试、构建、Git、非 Git 快照、冲突检测和恢复。

### 明确不做

- 不自行批准高风险操作。
- 不接受绕过 M3 的直接调用。
- 不自行决定是否创建 Git 提交。
- 不自动推送远端。
- 不使用破坏性强制重置清理用户工作区。

### 必须交付

- 文件读取、搜索、修改和 Diff。
- PowerShell/CMD 子进程启动、输出、超时、取消和进程树回收。
- 项目检查、测试、构建、静态检查和格式检查入口。
- Git 原有修改与任务修改区分、任务分支、暂存和本地提交。
- 非 Git 基线、单文件恢复、修改前恢复和任务基线恢复。
- 外部文件改变后的基准版本冲突检测。
- 工具调用结果中的退出码、输出、错误、耗时、影响路径和恢复能力。

### 必须测试

- 未持有有效写入租约时拒绝写入。
- 命令超时和取消后不存在失控子进程。
- 外部编辑冲突不会被自动覆盖。
- Git 原有未提交修改不会被清理或混入任务提交。
- 非 Git 恢复结果与基线校验一致。
- 应用崩溃后不会自动重复执行命令。

## 12. M5 任务卡：项目数据、审计与恢复状态

### 目标

在项目内 `.multi-agent` 保存可审计、可迁移和可恢复的任务事实，使异常退出后能够还原任务状态而不重复外部副作用。

### 明确不做

- 不保存明文 API Key。
- 不把数据库状态当作唯一磁盘事实。
- 不自动重新批准或重放命令。
- 不允许 UI 直接读写底层存储。

### 必须交付

- 任务、事件、消息、审批、证据、工具调用、文件变化、检查点和报告的存储边界。
- 原子写入、损坏检测、事务或等效一致性方案。
- Schema 版本和迁移验证。
- 异常退出后的最近稳定检查点读取。
- 单个任务记录删除和影响说明。
- 日志脱敏、索引和诊断导出边界。

### 必须测试

- 重复事件不会产生重复副作用记录。
- 中途写入失败不会留下无法解释的半状态。
- 旧版本数据迁移可验证、失败可恢复。
- 删除任务记录不会删除项目业务文件。
- 异常退出后记录状态与实际磁盘状态可以重新核对。

## 13. M6 任务卡：本地服务与桌面通信

### 目标

连接 Electron 工作台与 Python 内核，负责本机服务生命周期、会话鉴权、命令传递、流式事件、断线重连和退出清理。

### 明确不做

- 不在通信层实现编排规则。
- 不在通信层决定审批结果。
- 不向局域网或公网开放服务。
- 不让 UI 直接调用模型或项目工具。

### 必须交付

- 只监听 `127.0.0.1` 的本机服务边界。
- 临时会话鉴权、来源验证和重连策略。
- 命令请求、事件流、取消、健康检查和版本协商。
- Electron 启动、检测、关闭 Python 服务和子进程清理。
- Python 服务异常退出后的明确 UI 状态。
- 协议不兼容时的阻止和诊断信息。

### 必须测试

- 未鉴权连接被拒绝。
- 桌面端断线重连不重复提交命令。
- Python 服务崩溃时 UI 不显示虚假完成。
- 桌面端退出后不存在失控服务进程。
- 旧版本前端和新版本后端不会静默误用不兼容协议。

## 14. M7 任务卡：Electron/React 工作台

### 目标

实现统一桌面工作台，用公开事件呈现任务、群聊、审批、Diff、终端、测试、风险、恢复和设置，并允许用户随时介入。

### 明确不做

- 不做完整 IDE。
- 不在前端实现权限和审批门禁。
- 不把 API Key 放入普通前端存储。
- 不直接访问项目文件、数据库、Shell 或模型供应商。
- 不自行猜测或修改后端协议。

### 必须交付

- 项目选择和任务创建。
- 任务阶段和参与者状态。
- 全量群聊、模型标签、角色、证据和错误展示。
- 用户插话、`@智能体`、暂停、继续、停止、换主管、换执行者和重新分工入口。
- 审批卡片及批准、拒绝、修改后重试和终止选择。
- 文件树、Diff、终端输出、测试结果、风险和最终报告。
- 模型连接设置、连接测试和脱敏展示。
- 角色创建、编辑、启停和模型分配。
- 异常退出后的未完成任务和恢复选择。

### 必须测试

- 先使用 M0 Mock 服务完成界面契约测试。
- 长流式消息下界面保持可操作。
- 暂停和停止操作有明确反馈，不伪造后台状态。
- 审批信息展示完整，不以默认操作代替用户决定。
- 断线、重连、错误和部分数据缺失时仍能展示真实状态。

## 15. M8 任务卡：测试、故障注入、打包与验收

### 目标

独立验证所有模块、跨模块连接和真实 Windows 使用方式，确保系统符合主方案的八个核心验收场景。

### 独立性要求

- 默认只读审查业务实现。
- 测试失败时提交证据和复现步骤，不直接降低标准。
- 如需修改测试基础设施，只修改测试负责区域。
- 修复由对应模块负责人完成，验收 AI 负责复验。

### 必须覆盖

- 公共契约兼容性。
- 状态机和唯一写入者。
- 三类模型连接、流式、取消和失败降级。
- 危险操作审批和程序层拦截。
- 敏感信息阻止和日志脱敏。
- Git 原有修改保护和禁止自动推送。
- 非 Git 快照恢复。
- 外部文件冲突。
- 异常退出恢复和进程清理。
- Electron 与 Python 本地通信。
- Windows 安装、升级、卸载和残留检查。
- 文档同步与临时残留检查。

### 最终输出

- 逐项验收报告。
- 真实命令、退出码、日志、Diff、哈希和必要界面证据。
- 通过、失败或未验证结论。
- 失败影响、复现步骤、修复责任和复验范围。
- 第三方依赖和许可证核查结果。

## 18. 开发波次与并行边界

### 第 0 波：契约实现和模拟环境

仅由 AI-A 主导：

- 依据 M0 v0.5.1 最终版实现公共类型、Schema 和契约测试，不再生成新候选版本。
- 确定模块所有权和禁止修改范围。
- 提供 Fake Provider、Fake Tool、Fake Approval 和示例事件。
- 建立契约测试入口。

完成门槛：契约自动化测试通过，Fake Provider、Fake Tool、Fake Approval 可按同一契约互操作，已知差异有明确的接口变更单而不是私自改变语义。

### 第 1 波：基础模块并行

- AI-A 使用假依赖建立 M1 状态机骨架。
- AI-B 开发 M3、M4、M5 的接口内实现。
- AI-C 开发 M2、M6 和使用 Mock 服务的 M7。

这一波允许模块内并行，不允许改变 M0 语义。发现不足时提交接口变更单。

### 第 2 波：有限集成

- 先接入一个模型和只读项目工具。
- 接入任务保存、暂停、继续、取消和审批等待。
- 接入唯一写入者和受控文件修改。
- 接入 Git 或非 Git 的一种恢复路径，再补另一种。

跨模块胶水只由 AI-A 修改。AI-B 和 AI-C 提供接口修复，不同时改集成文件。

### 第 3 波：完整闭环

- 接入三个模型。
- 完成公开讨论、主管、备用主管和重新分工。
- 完成方案批准、代码修改、测试、独立审查和报告。
- 完成 Git 提交审批与非 Git 恢复。

完成门槛：真实 Windows 项目上能跑通一项小功能，且没有绕过审批、并发写入或记录失真。

### 第 4 波：独立验收和发布

- 运行八个核心验收场景。
- 注入断网、限流、流式中断、强制退出、外部文件修改和命令超时。
- 检查安装包、升级、卸载、进程残留和数据删除。
- 检查 README、接口、安全、测试和当前状态文档。
- 检查临时文件、调试代码、测试旁路和写死数据。

## 19. 合并和变更规则

### 19.1 模块交付

模块负责人只提交自己负责范围内的变更，并附测试证据。不得顺手重构其他模块、升级全局依赖或修改公共协议。

### 19.2 接口变更单

接口变更单至少包含：

- 当前协议版本。
- 发现的问题和复现证据。
- 建议改变的语义，而不只是字段名称。
- 受影响模块。
- 兼容和迁移方案。
- 需要补充的测试和文档。
- 不变更时的风险。

只有 AI-A 可以批准并合入公共契约改变。涉及产品行为、安全边界、数据结构、接口协议或验收标准时，必须交由用户决定。

### 19.3 合并门槛

每次正式合并前必须完成：

1. 模块单元测试。
2. 公共契约测试。
3. 受影响的集成测试。
4. 安全和恢复回归检查。
5. 文档同步判断。
6. 临时残留检查。
7. 未验证项和已知风险报告。

## 21. 禁止事项

- 禁止多个 AI 同时修改公共协议、状态机、审批规则或同一核心文件。
- 禁止模型适配器直接操作项目文件或命令行。
- 禁止 UI 直接连接模型、读取数据库、保存明文密钥或执行 Shell。
- 禁止工具层自行批准操作或决定任务完成。
- 禁止用提示词代替安全门禁、写入锁或路径校验。
- 禁止把 Mock 测试当作真实接口和真实 Windows 验收。
- 禁止实现 AI 只凭自己的单元测试宣布安全或恢复通过。
- 禁止未经批准自动提交、推送、安装、下载执行或访问项目外路径。
- 禁止为了并行效率而让不同 AI 各自定义消息、错误和状态格式。
- 禁止在合并前遗留调试打印、一次性脚本、临时安全旁路和写死假数据。
